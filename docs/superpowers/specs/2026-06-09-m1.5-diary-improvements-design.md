# M1.5: 日記運用改良 設計ドキュメント

- **作成日**: 2026-06-09
- **対象**: 既存 M1（日記 CRUD）の利用体験を高める改良
- **位置づけ**: 仕様 §1.1 機能要件には無い改良。M4（認証・公開）に進む前に「個人ユース」での実用度を上げる
- **ステータス**: 設計合意済み（合意日 2026-06-09）

## 1. 概要

M0〜M3 で「書く・見返す・AI 分析・MBTI」までは揃ったが、実機で触ると以下の不便がある：

1. **書き忘れた日が埋められない** — 過去未記入日のカレンダーセルが死んでいる
2. **書いた内容を消せない** — 試し書き・誤字行を捨てる手段がない
3. **長文が読みにくい** — Markdown 記法を入れても plain text として表示される
4. **書いた瞬間の見た目が確認できない** — 保存→再読込しないと完成形が見られない
5. **書く動機が弱い** — 連続記入の手応えが画面に出ていない

M1.5 はこれらを最小工数で解消する。

### 1.1 含める機能（5 つ）

1. バックデート編集
2. 削除機能
3. Markdown レンダリング（詳細ページ表示）
4. Markdown 編集プレビュー（エディタ内タブ）
5. 連続記入日数（streak）表示

### 1.2 含めない機能（YAGNI）

- 検索機能（蓄積量が増えてから）
- エクスポート（M4 公開時に）
- ベスト streak 記録の永続保存
- shadcn Dialog による削除確認（標準 `confirm()` で開始）
- Markdown 画像対応（ストレージ要件が別件）
- リッチテキストエディタ（plain text に Markdown 記法のままで十分）

```
   │   │   編集: Textarea                    │  │

   │   │ [保存] [削除]                       │  │
   │   └──────────────────────────────────────┘  │
   │                                            │
   └─ /diary/[date] ─────────────────────────────┤
       │                                        │
       ├ 過去日 + entry あり (defaultTab=preview) │

       └ 未来日 / 不正形式 → 404
```

### 2.1 主要な設計判断

| 観点 | 決定 | 理由 |
|---|---|---|
| view/edit 切替 | エディタ内 Tabs（shadcn）で同一ページ内 | URL `?edit=1` より直感的、編集中プレビュー要件と統合 |
| Markdown 描画 | `react-markdown` + `remark-gfm` + `@tailwindcss/typography` | 業界標準、サニタイズが安全側、`prose` クラスで shadcn と統合 |
| Streak の起点 | 「今日 or 昨日」のどちらかから遡って連続日数 | 朝の段階で前日連続が壊れない |
| 削除確認 | ブラウザ標準 `confirm()` | shadcn Dialog は後回し（YAGNI） |
| 削除後の遷移 | 常に `/` へ | 「書き直し or 新しい日記」の自然な動線 |
| バックデート日付の範囲 | 「今日以前」のみ | 未来日付に書く意味がない |

## 3. 機能ごとの詳細仕様

### 3.1 バックデート編集

**フロー:**

1. `/history` のカレンダーで「過去日付かつ未記入」のセルをクリック
2. `/diary/2026-06-04` に遷移
3. 詳細ページが entry なしを検出 → **空エディタを表示**（既存の 404 動作を変更）
4. 保存すると、その日付で entry が作られる（`saveDiaryEntry` がそのまま使える）

**変更点:**

- `components/diary/DiaryCalendar.tsx`
  - 過去未記入セル: 現在は `<div>` (静的) → `<Link href="/diary/[date]">` に変更
- `app/diary/[date]/page.tsx`
  - 既存: `if (!entry) notFound()` → 変更: 過去日付なら空エディタ
  - 未来日付: `notFound()` のまま

**判定ロジック:**

```typescript
const { date } = await params;
if (!DATE_PATTERN.test(date)) notFound();
const today = todayInTokyo();
if (date > today) notFound();  // 未来日付は 404
const entry = await getDiaryEntry(date);
// entry が undefined でも、過去日付ならエディタを表示
```

### 3.2 削除機能

**UI:**

- `DiaryEditor` の保存ボタンの右に「削除」ボタン
- `bg-destructive` カラー、視覚的に区別
- 表示条件: `initialContent` が空でない（新規作成時は出さない）

**フロー:**

1. 削除ボタンクリック
2. `window.confirm("この日記を削除しますか？")` で確認
3. OK → Server Action `deleteDiaryEntry(entryDate)` 呼び出し
4. 成功 → `redirect('/')`

**Server Action:**

```typescript
export async function deleteDiaryEntry(entryDate: string): Promise<SaveResult> {
  try {
    await db.delete(diaryEntries)
      .where(and(eq(diaryEntries.userId, USER_ID), eq(diaryEntries.entryDate, entryDate)));
    revalidatePath('/');
    revalidatePath('/history');
    revalidatePath(`/diary/${entryDate}`);
    return { ok: true };
  } catch (err) {
    console.error('Failed to delete diary entry:', err);
    return { ok: false, error: '削除に失敗しました' };
  }
}
```

### 3.3 Markdown レンダリング

**範囲:** 「プレビュータブ」「詳細ページのデフォルト表示」の 2 か所で同じコンポーネントを使う

**コンポーネント:**

```tsx
// components/diary/DiaryMarkdown.tsx
import ReactMarkdown from 'react-markdown';
import remarkGfm from 'remark-gfm';

export function DiaryMarkdown({ content }: { content: string }) {
  return (
    <div className="prose prose-neutral dark:prose-invert max-w-none">
      <ReactMarkdown remarkPlugins={[remarkGfm]}>{content}</ReactMarkdown>
    </div>
  );
}
```

**サポート構文:**

- 見出し (`# H1`, `## H2`)
- 太字 (`**bold**`), 斜体 (`*italic*`)
- リンク (`[label](url)`)
- リスト (順序 / 非順序)
- コード (`` `inline` ``, ```` ```block``` ````)
- GFM: テーブル, 打消し線, タスクリスト, 自動リンク
- 生 HTML は無効化（react-markdown のデフォルト）

**非サポート:** 画像（M1.5 範囲外）

**スタイル:** `@tailwindcss/typography` の `prose` クラスで自動装飾。`prose-neutral` で shadcn の neutral カラーパレットと統合。

**改行の扱い:** Markdown の段落区切りは空行が必要だが、既存の日記は単純な改行で書かれている。`react-markdown` のデフォルトでは単一改行は無視される。**意図的な仕様**として：

- 現状のままにする（plain text として書いた日記は段落分離されず1段落に見える）
- ユーザーが Markdown 記法を覚えたら段落分けを意識して書ける

これは `remark-breaks` プラグインで単一改行を `<br>` に変換することで回避可能だが、**M1.5 では入れない**。Markdown ネイティブな挙動を優先し、混乱を避ける。

### 3.4 Markdown 編集プレビュー

**UI:** DiaryEditor の上部に shadcn Tabs を配置

```tsx
<Tabs defaultValue={defaultTab}>
  <TabsList>
    <TabsTrigger value="edit">編集</TabsTrigger>
    <TabsTrigger value="preview">プレビュー</TabsTrigger>
  </TabsList>
  <TabsContent value="edit">
    <Textarea ... />
  </TabsContent>
  <TabsContent value="preview">
    <DiaryMarkdown content={content} />
  </TabsContent>
</Tabs>
```

**`defaultTab` prop の決定:**

| 呼び出し元 | `defaultTab` | 理由 |
|---|---|---|
| `app/page.tsx`（今日） | `'edit'` | 書く動線が主 |
| `app/diary/[date]/page.tsx` (entry あり) | `'preview'` | 読む動線が主 |
| `app/diary/[date]/page.tsx` (entry なし、バックデート) | `'edit'` | プレビューする中身がない |

**実装注意点:**

- Tabs は **shadcn の Tabs component** を `pnpm dlx shadcn@latest add tabs` で導入
- Tab 切替は **クライアント側の状態**で、URL は変えない
- プレビュータブで `content` state を `DiaryMarkdown` に渡す → 編集中の最新内容で即プレビューできる

### 3.5 連続記入日数（streak）表示

**ロジック (`lib/diary/streak.ts`):**

```typescript
export function computeStreak(entryDates: string[], today: string): number {
  // entryDates: 既存の entry の YYYY-MM-DD のリスト
  // today: Asia/Tokyo の今日の YYYY-MM-DD
  
  const dates = new Set(entryDates);
  
  // 起点: 今日が記入済みなら今日から、未記入なら昨日から
  let cursor = dates.has(today) ? today : subDays(today, 1);
  if (!dates.has(cursor)) return 0;  // 昨日も書いてないなら streak 0
  
  let count = 0;
  while (dates.has(cursor)) {
    count += 1;
    cursor = subDays(cursor, 1);
  }
  return count;
}
```

**表示:**

- `app/page.tsx` のタイトル下に `🔥 N 日連続記入中`
- N === 0 のときは何も表示しない
- `lib/calendar/month-grid.ts` の `addDays(date, -1)` を流用

**なし。** すべて表示層・操作層の変更で、DB スキーマは変更しない。

## 6. テスト方針

- **`lib/diary/streak.ts`** は純粋関数 → Vitest で単体テストを書く（後付け可能）
- それ以外は手動 E2E スモークで確認：
  - バックデート: 過去未記入セルクリック → 空エディタ → 保存 → カレンダーで塗りつぶしに変わる
  - 削除: 既存日記の削除ボタン → confirm → 削除 → カレンダーで塗りつぶしが消える
  - Markdown: `# 見出し` を書いて保存 → 詳細ページで見出しが描画される
  - プレビュー: 編集中に「プレビュー」タブ → 即描画
  - Streak: シードで 7 件入れて `/` を見ると `🔥 N 日連続記入中` 表示

## 7. リスクと対処

| リスク | 対処 |
|---|---|
| `react-markdown` v9 系で改行挙動が変わっている可能性 | context7 で API 確認、`remark-gfm` のバージョンも合わせる |
| `@tailwindcss/typography` が Tailwind v4 で挙動が違う | Tailwind v4 では `@plugin '@tailwindcss/typography'` を globals.css で指定 |
| shadcn Tabs が base-nova スタイルで提供されないか古い形式 | `shadcn add tabs` 実行時にエラーなら確認、最悪自前 |
| Backdate で日付が「明日」になっている境界（タイムゾーン） | `todayInTokyo()` を使い、`date > today` の比較で防ぐ |
| 削除直後に `redirect` が AI 分析キャッシュを更新しない | `weekly_insights` / `mbti_snapshots` は削除でも無効化されない (=分析が古いままでもクラッシュしない設計) — 明示的に放置 |
| Markdown で書いた既存の plain text 日記が表示崩れ | 既存日記は段落分けされていないだけで読めるはず。表示確認で対処 |
